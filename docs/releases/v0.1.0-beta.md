# AYR v0.1.0-beta

## What it is

First public beta of AYR (Arquitect Your Repository), a portable workflow skill for project interviews, proportionate repository structure, reviewed capability discovery and coordination with existing skills.

## Included

- Adaptive questions before project changes, with reuse of existing answers.
- Skill and agent selection by project need, with source/license/permission review.
- Explicit task ownership, handoffs and verification evidence.
- Optional GSD routing that preserves an existing project's state.
- Claude/Codex installation guidance and an uppercase AYR command adapter.

## Beta scope

Instruction-only software; it does not impose a sandbox, install optional skill collections or certify third-party safety. Current client capabilities and installed resources determine which routes are usable. macOS installation and full multi-phase GSD execution are not certified by this release. Discovery, a bounded progress handoff and complete project delivery are different claims.

Release-specific observed checks are recorded in [the evaluation record](../evaluation.md). Package validation, operating-system installation tests and bounded client scenarios have different coverage. Please report issues with a minimal non-sensitive reproduction and client versions.

## Release checks

- Clean repository created from an exported source tree, without previous repository history. A known historical commit from the previous repository is not found in this repository.
- Windows and Linux CI pass: three package checks plus four native installation scenarios per operating system; the other operating system's four tests are skipped intentionally.
- Native installation tests use real local Git clone/checkout and real directory junctions/symlinks inside disposable homes. They verify successful activation and refusal of existing installs, modified staging and empty revisions. The remote clone URL is redirected to a local source for these tests; anonymous public network installation is a separate check.
- Standalone client probes are **blocked, not passed**: Claude recognizes the skill but reaches a usage limit before invocation; Codex rejects the skill/resource reads under its execution policy. Those probes did not complete an AYR interview or live GSD handoff.
- In the attempted progress-only GSD scenario, the seven planning files remained unchanged. That proves preservation in the blocked run, not a successful handoff.
- A later in-session agent demonstration loaded AYR, asked three questions before writing files, received a fictional client's answers and built a working standard-library Python reading-list CLI. Its application suite passed ten tests; a separate coordinator exercised normal and failure flows with new data. This uses the current session's native tools, not a separate client CLI invocation or a GSD handoff.

Treat optional orchestration and cross-client workflow behavior as experimental until the blocked probes can be completed. Static review and green package CI are not substitutes for that evidence.
